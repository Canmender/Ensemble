# 合鸣插件开发指南

> 面向插件作者。读完第一章你就能跑通第一个插件；三章覆盖全部官方 API 面。
> 所有示例在无密钥环境可运行（不依赖 LLM provider）。
> 参考实现：`server/src/plugins/builtin/daily-reminder.ts`（本指南第一章的素材）。

## 第一章：第一个插件（每日提醒）

### 1.1 插件是什么

合鸣插件 = 一个**候选定义**（CandidatePlugin）+ 一份 **manifest**（清单即权限）。
用户在设置页启用后，插件实例在**该用户自己的作用域**内运行——同一插件，
用户 A 和用户 B 是两个独立实例，互不影响、数据隔离。

```
服务器 plugins/ 目录（管理员预置候选集）
   └─ 你的 CandidatePlugin ──→ 用户「启用」──→ user:<uid>:<pluginId> 实例
                                                   ├─ 自己的 KV 命名空间
                                                   ├─ 自己的定时器配额
                                                   └─ disable 即整体消失
```

### 1.2 manifest：清单即权限

```ts
import type { CandidatePlugin } from "../per-user";

export const myPlugin: CandidatePlugin = {
  manifest: {
    id: "daily-reminder",        // kebab-case，全局唯一
    name: "每日提醒",             // 设置页显示名
    version: "0.1.0",            // semver
    description: "每天定时向指定会话发送一条提醒消息",
    scheduled: 1,                // 声明的定时任务数（计入每用户上限 20）
    eventsOn: [],                // 声明监听的事件（须命中白名单前缀）
  },
  create: (runtime) => ({ /* 第二章 */ }),
};
```

校验规则（zod，违反即拒绝注册）：`id` 小写字母开头的 kebab-case；`version` semver；
`scheduled` 0-5。**manifest 里没声明的能力就没有**——这是权限模型的地基。

### 1.3 安装与生命周期

把插件文件放进 `server/src/plugins/builtin/` 并在 `context.ts` 注册候选：

```ts
userPlugins.registerCandidate(myPlugin);
```

生命周期由内核托管：

| 动作 | 发生什么 |
|------|---------|
| 用户 enable | mount 实例 → `create(runtime)` → `install(ctx)` 执行 |
| 用户 disable | unregister → disposer **逆序**清理（定时器/监听器全消失） |
| 改配置保存 | dispose 后带新配置重挂（热重启） |
| install 抛错 | 已登记的副作用自动回滚，状态 failed，其他用户不受影响 |

**纪律：install 里产生的一切资源（定时器/监听器）都必须经 `ctx.effect()` 登记**——
这是"disable 后零残留"试金石的全部秘密。

### 1.4 runtime 与 config

`create(runtime)` 拿到三样东西：

```ts
interface UserPluginRuntime {
  manifest: PluginManifest;   // 你的清单
  userId: string;             // 本实例归属的用户
  kv: PluginUserKv;           // 本实例专属的 KV 存储（第二章）
  config: unknown;            // 用户在设置页保存的配置 JSON
}
```

> **ctx 从哪来（重要，曾踩坑）**：`runtime` 里**没有** `ctx`——宿主能力（事件、服务发现）
> 通过 `install(ctx)` 的参数注入。两者的生命周期不同：
>
> - `runtime`：create 工厂调用期存在（读 manifest/kv/config）
> - `ctx`：install 注入后**与实例共存亡**——异步回调（动作处理器、定时器）里要用 ctx，
>   就在 install 里用闭包捕获：
>
> ```ts
> create: (runtime) => ({
>   install: (ctx) => {                    // ← ctx 只从这里来
>     // 异步回调捕获真 ctx（错误示范：试图用 runtime.ctx —— 那里没有这个字段）
>     ctx.effect(() => {
>       const timer = setInterval(() => {
>         const sink = ctx.tryGet("events");  // 闭包里的 ctx，随时可用
>         // ...
>       }, 30_000);
>       return () => clearInterval(timer);
>     });
>   },
> })
> ```

## 第二章：事件与 KV

### 2.1 监听事件

```ts
create: (runtime) => ({
  install: (ctx) => {
    ctx.on("chat/message", (payload) => {
      const msg = payload as ChatMessagePayload;
      logger.info(`[${runtime.manifest.id}] ${msg.agentId}: ${msg.content.slice(0, 50)}`);
      // 观察者：返回 undefined 即可，下游继续
    });
  },
})
```

白名单前缀（manifest.eventsOn 须与之匹配）：`chat/`、`run/`、`device/`。
**`tool/confirm` 不对插件开放监听**——它是宿主的 HITL 决策面。

### 2.2 发消息（吃自己种的菜）

向会话发消息不要直调 hub——走事件总线，与 hub 广播、卡片渲染同一条链路：

```ts
const events = ctx.tryGet<EventSink>("events");
events?.emit("chat/message", {
  runId, jobId: undefined,
  agentId: runtime.manifest.id,       // 来源标识用你的插件 id
  role: "assistant",
  content: "你好",
  id: `${runtime.manifest.id}-${Date.now()}`,
  seq: -1,
  userId: runtime.userId,
});
```

`events` 服务由宿主提供（fail-closed：拿不到就跳过本轮，别硬编码兜底路径）。

### 2.3 KV：你的私有存储

```ts
runtime.kv.set("state", { nextAt: Date.now() + 3600_000 });
runtime.kv.get<{ nextAt?: number }>("state");
runtime.kv.del("state");
runtime.kv.list();  // 本命名空间全部键值
```

物理表主键是 `(userId, pluginId, key)` 三元——**你永远拿不到别的用户或别的插件的数据**，
也不必担心写脏别人的。适合存：调度状态、游标、计数器。大对象/敏感值不要放这里。

## 第三章：配置与 settings 表单

### 3.1 读用户配置

用户在设置页保存的配置经 `runtime.config` 注入（已 JSON 反序列化）：

```ts
const cfg = (runtime.config ?? {}) as { time?: string; message?: string };
const time = /^\d{2}:\d{2}$/.test(cfg.time ?? "") ? cfg.time! : "09:00"; // 校验+默认值
```

**纪律：config 永远不可信**——类型断言 + 字段校验 + 默认值，缺一不可
（用户可能手填任何东西）。

### 3.2 settings 表单字段（现状）

web 端 `PluginsPanel.tsx` 的 `CONFIG_FIELDS` 按插件 id 声明表单字段：
key/label/placeholder/type。你的插件的字段声明加进那张表即可出现在设置页
（manifest 内嵌 schema 自动渲染在路线图上，届时此节更新）。

### 3.3 定时任务模式（daily-reminder 全文）

定时器的标准形态——effect 登记落库持久状态防重复触发：

```ts
create: (runtime) => ({
  install: (ctx) => {
    const state = runtime.kv.get<{ nextAt?: number }>("state") ?? {};
    if (!state.nextAt || state.nextAt <= Date.now()) {
      state.nextAt = nextOccurrence(time, Date.now());
      runtime.kv.set("state", state);            // 重启不丢、不重复发
    }
    ctx.effect(() => {
      const timer = setInterval(() => { /* 到点检查并触发 */ }, 30_000);
      timer.unref?.();
      return () => clearInterval(timer);          // disable 时自动清理
    }, "reminder-timer");
  },
}),
```

每用户 timer 配额 20：manifest.scheduled 是你的占用申报，mount 时累计校验。

### 3.4 API 速查

| 你拿到 | 能做什么 | 禁止 |
|--------|---------|------|
| `ctx.on(event, fn)` | 监听白名单前缀事件 | 监听 tool/confirm / 白名单外 |
| `ctx.tryGet<T>("events")` | 拿事件总线发 chat/message | 直调 hub |
| `ctx.effect(fn, label)` | 登记可逆副作用 | 裸 setInterval/addListener 不登记 |
| `runtime.kv.*` | 本命名空间 CRUD | 访问他人命名空间（架构上不可能） |
| `runtime.config` | 读用户配置 | 信任未校验的字段 |

### 3.5 上线检查单

- [ ] manifest 字段真实反映能力（多报=浪费配额，少报=被拒）
- [ ] 所有副作用经 ctx.effect 登记
- [ ] 定时器有 unref + disposer
- [ ] config 全部字段校验 + 默认值
- [ ] 发消息走 events 总线，agentId 用自己的插件 id
- [ ] 无密钥环境可安装运行（不依赖 LLM）
