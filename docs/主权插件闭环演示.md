# 用户主权插件 · 第一个完整闭环演示

> 投票插件的完整旅程：桌面装插件 → web 发起投票 → web/手机同时收卡 → 手机投票 → 双端卡片刷新。
> 前置：云端服务器已部署 v0.8.26+；桌面云端版与手机登录**同一账号**（或两账号互为好友同处一群聊——v1 演示用同一账号最简）。

## 0. 准备

1. **部署服务端**（管理员一次性）：服务器代码 ≥ v0.8.26（poll 插件内置候选集），`docker compose build && up -d`
2. **桌面端**：安装「合鸣云端版」setup.exe（≥ 0.8.26），首启向导填云端地址 → 登录
3. 手机端 ≥ 移动版含 PluginCardView 渲染的版本

## 1. 启用插件（桌面）

设置 → 插件 → 「群投票」开关打开。

背后发生的事：你的账号作用域里 mount 了一个 poll 实例（其他用户零感知）；动作处理器注册进 per-user 动作表。

## 2. 发起投票（两种方式任选）

**方式 A · 界面**（后续版本提供聊天页「发起投票」入口）

**方式 B · curl / API**（当前版本；见 `desktop/scripts/poll-curl-demo.sh` 完整脚本）：

```bash
# 登录拿 token 后：
curl -X POST "$HOST/api/users/me/plugins/poll/actions/create" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"runId":"<会话runId>","question":"周五团建去哪","options":["爬山","聚餐","KTV"]}'
```

→ 聊天流出现投票卡：问题标题 + 三个选项按钮 + 票数条。

## 3. 双端收卡

- **web（桌面）**：WS 推送 `chat.message`（attachment.type=plugin-card）→ 五模板分派渲染 poll 卡
- **手机**：同一条 WS 消息 → PluginCardView 按 shared 协议渲染同构卡片

## 4. 手机投票 → 双端刷新

在手机上点一个选项：

```
手机点击 → POST /api/users/me/plugins/poll/actions/vote {pollId, optionId}
        → 你的 poll 实例计票（state 落 plugin_kv，重启不丢）
        → 经事件总线发新版本卡片消息
        → 服务端广播 → web 与手机的聊天流各追加一张新票数的卡片
```

## 5. 隔离验证（可选，体现"用户主权"）

用另一个账号登录 web：不启用 poll 插件时点选项 → 404「未知动作」（该用户的实例不存在）；启用后再点 → 正常计票。**每个人的插件、数据、配置互不可见。**

### 架构速记（给好奇的实现者）

| 环节 | 机制 |
|------|------|
| 插件实例 | (userId, pluginId) = 内核命名空间插件 `user:<uid>:<pid>` |
| 卡片传输 | MessageAttachment.type="plugin-card"，PluginCardPayload 内联 |
| 动作分发 | POST /api/users/me/plugins/:id/actions/:action → per-user 动作表 |
| 计票持久化 | plugin_kv 三元键 (userId, pluginId, key) |
| 广播链路 | 插件 emit chat/message → chat-broadcaster → hub（与普通消息同一条路） |
